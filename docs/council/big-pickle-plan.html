Council draft · Big Pickle · not the agreed plan

Seeds as rows, replace as one rolling card

The test for every feature: an agent says it once over MCP, and every screen agrees. Built-ins are cloned per user. Experiments do not need a migration.

Introduction

Manager stops being a checkbox list and becomes the record of a life that has shape. A task can carry a date, a time, a place, a schedule, a priority, a deadline, a counter, and links into events, seasons, quests, categories, and spaces.

The agent connects at https://manager.labdm.dev/mcp, calls whoami, and writes Convex. The SPA, Tauri, Apple, and Android read the same functions. Manual entry stays the fallback. Meaning lives only in the Convex service. No public REST.

“Dailies never stack” is the wrong universal. A series declares behavior. replace keeps one live undone instance and, at rollover, patches that same instance onto the new period. Yesterday’s dish cannot be washed, and it does not remain as a second card. Completed history still counts. stack mints a new occurrence per period. Missed journal days stay completable. The UI may suggest which behavior fits. It cannot forbid the other.

A planned date is when you will do it. A deadline is when it stops counting. A reminder is when you are told. Taxes escalate. A promo retires. “Limited window” is internal. A plain pack says “closes Friday”. Season length, single attachment, and known-ahead quests are defaults, not schema bans.

Three positions

  • Soft delete is absolute. Detach, leave, and expire are tombstones too. A purge job is horizon.
  • Sharing is a space. Private rows keep ownerId. Membership grants access to what was attached. Not a per-task ACL soup, and not “everything must already live in a space”.
  • Slugs are strings. replace and stack ship in a registry. A new behavior is a registry entry plus a seed, not a Convex union migration.

Task fields keep dueAt as the planned instant (wire float, unchanged for current clients). allDay defaults true. deadlineAt and remindAt sit beside it. Also location, priority string, optional priorityRank, overduePolicy, seriesId, occurrenceKey, presentationId, deletedAt.

Other tables: windows, events, seasons, categories, series, progressions, quests with steps embedded in the document, spaces, space_members, space_entities, links (isPrimary is only a flag), presentation_packs, overdue_policies. Seeds are cloned per user so Household can be renamed.

Replace invariant: at most one live undone occurrence; rollover patches it forward. Stack invariant: (seriesId, occurrenceKey) unique among live rows. Many links may be primary. The core will not throw.

Behaviors and policies

Replace: dishes, today’s meds. Stack: journal, water, pages. Policies: retire (promo), escalate (taxes, rent, passport). Priority: low / normal / high / urgent at ranks 0 / 10 / 20 / 30. Custom strings may bring their own rank.

Starters

  • Progressions: move 30 days, read a book in pages, journal streak
  • Quests: broken-window (emergent), morning-launch (known), tax-season (known)
  • Seasons: winter, tax-season, project-sprint
  • Limited: christmas-market weekend, mcdonalds promo (retire), taxes (escalate)
  • Packs: plain, gacha-night, gacha-winter, focus. Tokens and copy only. A pack cannot add a validation rule.

Worlds × slices

Default. Vertical worlds: Today, each category, Quests, Seasons, Spaces, Progress. Horizontal strip inside a world: Daily, Weekly, This event, Limited, Done, All. Any pair is legal. board:slice takes { vertical, horizontal } and returns tasks, bars, and quest panels. No whitelist.

Dense worlds (Today, Seasons) draw cards. Scan worlds (Household, Weekly) draw rows. A bar is a card in Progress and a row inside Health. Quests get their own world: locked, available, done. An emergent next step reads “next step unlocks when this is done”.

Calendar-first. Windows vertical, categories horizontal. Same query, axes swapped. Deadlines are end caps.

Campaign map. Seasons and quests vertical, acts horizontal. Bars across the top. Limited windows are timed gates. This is what gacha-night would ship as its default layout hint.

Unknown pack ids fall back to plain. Layout hints travel in the pack row, not in a schema fork.

User flows

  1. Dishes. Daily series, behavior replace. At midnight the undone instance is patched onto tomorrow. One card. Done history still feeds a household progression.
  2. Journal. Daily series, behavior stack. Wednesday shows Monday, Tuesday, and Wednesday. No core cap. A pack may collapse old rows.
  3. Taxes. dueAt is a quiet work block. deadlineAt is 30 Nov. Policy escalate, priority high. After the deadline, priority becomes urgent and the task moves to the top of Today.
  4. Burger. Limited window, policy retire. Monday it is soft-deleted out of slices, shown once under Expired, and can be restored. The row remains.
  5. Broken window. Quest reveal mode emergent. Step 1 is “call the landlord”. Later step titles start undefined. On complete, the agent writes “go to the mall”, or money, or a repairer. A known checklist shows every step up front.
  6. Book. Metric pages, target 320. +18 moves the bar to the new current. It is a row in Project and a card in Progress. A 30-day exercise series increments from completed instances.
  7. Flat 4. Attach the household category, the dishes series, and winter. The partner checks off dishes. Ownership stays with the creator. Detach drops visibility and does not delete.
  8. Market mail. create_window for 20–22 Nov, create_event “Christmas market”, a task, a Winter season, a 5-day snow-walk progression. The user sees Winter × This event without a refresh.

Technical plan

Service modules split by entity. One schema, one auth gate. Every list uses a by_owner_deleted index with deletedAt === undefined. taskView keeps today’s id, title, done, dueAt, ownerId and adds defaults: all-day, priority normal, policy none. remove patches deletedAt. Add restore. Links and memberships are soft-deleted too.

seriesService.materialize is idempotent. Replace patches the live undone row or inserts a fresh one if it was done. Stack inserts one row per elapsed period. Overdue in milestone 1 is derived on read (effectivePriority, isExpired). A scheduled handler that applies retire or escalate waits until milestone 2.

MCP tools, all thin: existing task tools plus update_task and restore_task; window, event, season, and series CRUD; record_progress; complete_quest_step and reveal_quest_step; categories and packs; space invite and attach; attach / detach; board_slice. Rebuild api/ with pnpm build:api.

Native clients ignore unknown keys. No client computes overdue, recurrence, or access. Migration is additive fields first, then the delete flip, then seed backfill on next signed-in query. dueAt needs no conversion.

Schema sequence: M1 tasks + categories + links + series, no seasons. M2 windows, events, seasons, packs, policies. M3 progressions and quests. M4 spaces. M5 pack content only, no new core tables.

Arguments this draft wants

  • Rolling replace loses “I skipped Tuesday”. That is intentional. Done history remains. An audit of skips is the counter-proposal.
  • Can a space member edit anything shared, or only what they created? Lean yes for household tasks, no for season definitions.
  • If the council wants “event” to mean every cadence, rename the named-happening entity before MCP ships.
  • String slugs make typos runtime errors. Unions make every experiment a migration. This draft picks strings.
  • Stack backfill after a month away can flood an ADHD board. Cap it in the pack.
  • create_task docs must say dueAt is the plan, deadlineAt is the last valid moment, remindAt is the ping.
  • A pack id unknown to Apple is the most likely cross-platform bug. One slug list, copied into each client.
